# 아키텍처

레짐(시장 국면) 기반 멀티 전략 시스템. 데이터가 아래에서 위로 흐르며
점점 "판단"으로 정제되고, 감성·리스크 레이어가 옆에서 적극도를 조절한다.
전체를 검증/리스크 프레임워크가 감싼다.

## 6개 레이어

읽는 순서는 아래(데이터)에서 위(주문 실행)로.

### 1. 데이터 레이어

모든 것의 토대. 가격(OHLCV), 재무, 뉴스/공시 텍스트, 금리·환율 같은
거시지표를 수집·정제해 저장한다. 여기서 데이터 품질이 나쁘면 위층이 모두
무너진다(garbage in, garbage out).

### 2. 국면 분류 레이어

"지금 어떤 시장인가"를 판정한다. 시스템의 심장부이자 가장 어려운 곳.
출력은 단일 라벨이 아니라 "추세 강도 0.7, 변동성 중간" 같은 연속 상태값이
이상적이다. 국면은 후행적으로만 명확해지므로(후행성 문제), 전환 시점의
신호 지연·whipsaw를 어떻게 다루는지가 시스템 전체 성패를 가른다.
칼같이 3분할하기보다 연속 스펙트럼 + 히스테리시스로 부드럽게 처리할 것.

상세: `docs/strategy/regime.md`

### 3. 전략 풀

국면별로 매핑된 전략 묶음. 예: 상승장 → 추세추종·모멘텀,
횡보장 → 평균회귀·페어트레이딩, 하락장 → 현금비중 확대·방어.
한 국면에 여러 전략, 한 전략에 여러 알고리즘이 들어간다(분산 효과).

상세: `docs/strategy/strategy-pool.md`

### 4. 감성·리스크 레이어

방향이 아니라 **크기**를 조절한다. 뉴스 감성·지정학 리스크 점수로
전체 노출(적극도)을 정한다. 액셀·브레이크 역할이지 핸들이 아니다.
핸들(방향)은 국면·전략이 잡는다.

상세: `docs/strategy/sentiment-risk.md`

### 5. 메타 레이어

여러 전략이 동시에 신호를 낼 때 자본을 어떻게 나눌지 결정한다.
전략 간 상관관계를 보고 중복 베팅을 걸러낸다. 이게 없으면 분산투자처럼
보이지만 실은 같은 베팅을 여러 번 하는 함정에 빠진다.

상세: `docs/strategy/meta-allocation.md`

### 6. 주문 실행 레이어

최종 결정을 실제 주문으로 변환한다. AI나 복잡한 판단이 아니라
명확한 규칙으로만 작동해야 안전하다. 전략 스택은 "목표비중"만 만들고,
실제 주문은 목표 ↔ 현재 계좌의 차이를 정산(reconcile)해 나온다.
계좌 상태 읽기·정산·토스증권 API 매핑·실행 모드는 `docs/coding/execution-and-data.md`.

## 척추 바깥: 관측·제어 표면

위 6개 레이어가 트레이딩 척추(데이터→판단→주문)다. 그 **바깥에** 백테스트
확인·보정 대시보드와 실거래 모니터링 대시보드가 붙는다. 이건 7번째 레이어가
아니라 읽기 위주 관측 표면이다 — UI는 엔진 산출물을 읽고, 운영 제어(킬스위치
등)만 쓴다. 매매 로직은 절대 UI에 두지 않는다. 상세: `docs/coding/dashboards.md`.

## 한 사이클 데이터 흐름

```
① 국면 판정 (지금은 상승장)
  → ② 그 국면에 매핑된 전략 선택 (모멘텀·추세추종)
  → ③ 전략이 매수 후보 신호 생성
  → ④ 감성·리스크가 적극도 조절 (예: 노출 80%로 축소)
  → ⑤ 메타 레이어가 종목별 비중 결정
  → ⑥ 규칙 기반 주문 체결
  → 다음 주기에 ①로 복귀
```

## 설계 원칙

- **검증 프레임워크를 먼저 만든다.** 거래비용·슬리피지를 반영하고
  in-sample/out-of-sample을 분리하는 백테스트 엔진이 없으면 전략이
  진짜인지 우연인지 알 수 없다.
- **각 레이어를 독립적으로 갈아끼울 수 있게(모듈화)** 설계한다.
  국면 분류기를 바꿔도 전략 풀은 그대로, 전략을 추가해도 메타 레이어는
  그대로 작동해야 한다. 인터페이스(입출력 형식)만 고정한다.
- **AI는 4번 레이어에만 가둔다.** 방향을 정하는 1~3과 돈을 움직이는 6은
  명확한 규칙으로, AI(LLM 감성분석)는 적극도 조절이라는 보조 역할로만.
  AI가 오작동해도 시스템이 통째로 무너지지 않게 한다.
